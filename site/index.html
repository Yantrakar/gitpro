OPEN SOURCE · MIT · v0.4.0

The right git name, email and SSH key in every repository. For you, and for the AI agents that commit for you.

gitpro picks the identity by the repository's remote URL, not by the folder you cloned it into. It writes plain git and SSH config, so nothing runs in the background.

$ pipx install gitpro

GitHub PyPI VS Code Guide

Matched by remote URL

You describe each identity once: a name, an email, an SSH key, and the hosts and owners it belongs to. gitpro turns that into git's own includeIf rules and SSH host entries, so git picks the identity from the remote URL on every commit.

  • PLAIN CONFIG

    Ordinary git and SSH files in a marked block. No daemon, no wrapper around git.

  • PREVIEW

    gitpro setup shows every change before anything is written, and gitpro setup -n only shows.

  • BACKUPS

    Hand-written files are backed up, and gitpro uninstall removes everything again.

  • GUARD

    Optional hooks refuse a commit or push with the wrong identity and print the command that fixes it.

✗ gitpro: this commit would be committed as jane@personal.dev
  but origin (git@github.com:employer-org/app.git) belongs to
  identity work-github <jane.doe@employer.com>
  cause: user.email is set in the repo's .git/config
  fix:   git -C ~/work/github.com/employer-org/app config --unset user.email

Works with your git host

An identity is a host and, if you like, the owners under it, so any git host works, over SSH or HTTPS. The remote URL forms of these hosts are tested against real git on every change:

  • GitHub
  • GitHub Enterprise Server
  • GitLab.com
  • GitLab self-managed
  • Bitbucket Cloud
  • Bitbucket Data Center
  • Azure DevOps
  • visualstudio.com
  • Codeberg
  • SourceHut
  • Gitea
  • Gitee
  • Hugging Face
  • AWS CodeCommit
  • Launchpad

When a remote URL has a form the patterns miss, such as a user name in an HTTPS URL, a port, different letter case or git+ssh://, gitpro why says so and gives the fix.

AI agents commit too

Coding agents run git commit, git push and gh pr create on their own. gitpro checks each of those calls before it runs. When the identity is wrong, the call is denied with a reason, and the agent has to ask you.

  • HOOK

    A Claude Code PreToolUse hook, from gitpro setup or the plugin. It only denies; it never grants anything.

  • MCP

    A read-only MCP server, gitpro mcp or uvx gitpro mcp, so an agent can ask which identity a repository uses and why, and whether a commit would be blocked. Tools include why, setup, scan, audit, env and report. It is listed in the official MCP Registry as io.github.Yantrakar/gitpro.

  • APPROVAL

    Agents can read the answers, and the fix commands wait for your approval.

  • AUDIT

    gitpro audit finds commits made as the wrong identity or by an agent; --fix fixes the unpushed ones.

  • LLMS.TXT

    Agents can read gitpro.dev/llms.txt for the commands, the MCP tools and the docs in plain text.

Set up in a few minutes

Linux or macOS, Git 2.36 or newer, Python 3.9 or newer and OpenSSH.

  1. Install pipx if you don't have it. brew install pipx on macOS, sudo apt install pipx on Ubuntu.
  2. Answer a few questions, then say yes once. gitpro setup offers to look through your repos to find your identities, shows everything it will set up, and applies it after one yes. It never changes your repos.
  3. Ask a repository. gitpro why shows the identity it should use, the one it uses, and the fix if they differ.
  4. See what needs a fix. gitpro scan lists the repos that need attention and the command for each.
$ pipx install gitpro
$ gitpro setup
$ gitpro why
$ gitpro scan

Main commands

Every command has --help, and the ones that read have --json. The guide has the full list.

The main gitpro commands and what each one does
CommandWhat it does
gitpro setupSets up this machine after one yes: config, SSH keys, Git and SSH files, guard and agents. It offers to find your identities in your repos. -n only shows.
gitpro whyWhich identity a repository should use, which it uses, why, and the fix. --committer and --message ask whether a commit would be blocked.
gitpro scanLists your repositories by the identity git uses. --fix removes repository overrides, --lost adds the work that is only on this machine.
gitpro keysEach SSH key and where to register it. gitpro setup creates the missing ones.
gitpro guardGit hooks that refuse a commit or push with the wrong identity.
gitpro setup --agent claudeThe hook that stops an AI agent committing as the wrong identity.
gitpro auditFinds commits made as the wrong identity or with an AI agent.
gitpro clonegit clone with the identity, SSH alias and folder the URL calls for.
gitpro scan --lostUnpushed branches, stashes and dirty trees across your repositories.
gitpro uninstallRemoves everything setup wrote. Keeps your config and SSH keys.

Questions

Can I use more than one GitHub account on one computer?

Yes. Each account is an identity with its own name, email and SSH key. gitpro writes one includeIf hasconfig:remote.*.url block per identity, so git picks the identity from the repository's remote URL, and SSH offers only that identity's key. The same works for GitLab and other hosts.

Where does the configuration live?

In ~/.config/gitpro.toml, or wherever $GITPRO_CONFIG points. gitpro setup writes it for you; the guide covers the format if you prefer to edit it.

What does it change on my machine?

A block between # BEGIN gitpro and # END gitpro in ~/.gitconfig and ~/.ssh/config, one ~/.gitconfig-<id> file per identity, and the SSH host entries. Existing files are backed up first.

How do I undo it?

gitpro uninstall removes everything apply wrote and the global guard hooks. Your config and SSH keys stay.

Does it send anything anywhere?

No. Commands only go online when you pass --online, and then through gh, glab or ssh. gitpro report keeps a record of the last internal error and the last 20 blocked commits on your machine, without emails, paths or repo names, and shows you a redacted draft; it opens the issue form in your browser only when you say yes.

Does anything run when I use git?

Only the guard hooks, if you install them. Otherwise git reads the config gitpro wrote, and gitpro is not involved.

Which systems does it run on?

Linux and macOS, with Git 2.36 or newer, Python 3.9 or newer and OpenSSH.
